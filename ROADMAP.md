# Roadmap - OPEN work only

One line per item. No narrative. Shape:

```
CS-nnn - <one line> - acceptance: <testable condition> - tier: <0|1|2>
```

Closed work lives in `docs/LEDGER.md`. Aspirational and conditional-trigger items live in
`BACKLOG.md`. Items blocked on something outside the repo live in `docs/GATED.md`. An item
is in exactly one of those four places.

**ID blocks.** IDs are permanent and never reused. `CS-0nn` is the phase 0 scaffold block
and is closed - those entries are in `docs/LEDGER.md`, not here. Open items are numbered
in the hundreds block matching their phase: `CS-1nn` phase 1, `CS-2nn` phase 2, and so on
through `CS-7nn`. Gaps are expected and are never backfilled.

**Not listed here:** phase 0, which is being completed now and closes into
`docs/LEDGER.md`. Spikes S4, S6 and S8 are also absent - they are being settled in this
session and their results land as ADRs in `docs/adr/` with the decisions recorded in
`docs/LEDGER.md`. If any of the three comes back unsettled, it is filed here as a new item
rather than left implicit.

**Do not advance past a phase whose acceptance criterion is unmet.**

The adjudicator that found it RECUSED itself from granting it; route to a second adjudicator or the operator. Conditions to attach, from that handoff: redact at the render boundary (`emit`) and NEVER in `label_for` or `Unit.label`; keep the basename and repo-relative tail verbatim and strip only the directory prefix above the repo root or home; fail closed to a withheld token if the redactor is unimportable; fix all three `emit` channels at once or the leak moves rather than closes; leave `--text-stdin`'s literal `<stdin>` label alone; and cover `tools/edit_lint_check.py` in the SAME item, by test rather than by inspection, since it builds its own labels but emits through the same `gate.emit`. Expect ZERO tests to turn red - the only assertion pinning label shape is `tests/test_precommit_gate.py::test_verbose_lists_every_checked_unit`, which pins a basename; a red test there means the redaction went too far, so fix the redaction rather than the test.
CS-205 - Redact the remaining exception renderings outside the two CS-202 files - acceptance: a MECHANIZED repo-wide test, not a hand-maintained instance list, asserts that no tracked module renders an exception into a message without redaction, covering `scripts/install_hooks.py`, `tools/edit_lint_check.py`, `tools/memory_sync.py` and `clockspeed/data/version.py` - tier: 1 - NOTE: `scripts/install_hooks.py` is FROZEN and this item carries its own grant request. Also carries the residual left by CS-202: `traceback.print_exc()` in the gate's top-level crash handler still renders exception messages unredacted, which is not a formatting rendering and so fell outside CS-202's sweep.
CS-209 - Give the commit gate a per-value world-name EXCLUSION surface, a remedy clause, and a skip channel that actually prints on the authoritative path - acceptance: a value named in a `world_name_exclusions` key in the gitignored `config/local.json` is dropped AFTER discovery and reported through the existing skip channel without echoing the value; the world-name diagnostic names that key as the remedy; and the skip channel is proven to print on the path `.githooks/pre-commit` actually runs, by an end-to-end test rather than by passing the flags explicitly - tier: 1 - NEEDS ITS OWN FROZEN-FILE GRANT for `tools/precommit_gate.py`, and possibly for `.githooks/pre-commit`. NOTE: this REPLACES CS-208, which was DENIED on 2026-08-14 by measurement rather than by judgement - see `docs/LEDGER.md`. The denial's three load-bearing measurements: 16 matchable world names exist on this machine and the shortest is 4 characters, so any floor at or above 5 drops exactly one REAL world name and it then commits; the gate over all 117 tracked files exits 0, so the false positive CS-208 feared does not exist; and a floor of 4, 5, 6 or 8 turns ZERO of the 65 gate tests red, which proves the suite is BLIND to the change rather than that the change is safe. Narrowing a PII blocklist by default to pre-empt a collision that diagnoses itself to line and column is trading a certain fail-open for a diagnosable fail-closed. SEPARATELY FOUND while ruling on it, and the more valuable half: `.githooks/pre-commit` runs the gate with neither `--verbose` nor `--list-skipped`, and `emit` prints the skipped channel only under those flags, so the claim at `tools/precommit_gate.py:561-562` that a dropped value stays visible per CONVENTIONS section 15.1 is FALSE ON THE AUTHORITATIVE PATH. Every test in the suite passes those flags explicitly, so nothing in the tree asserts what the hook actually prints.
CS-210 - Ground the absent-`mMaxPotential` branch in the shipped document instead of in one hand-authored fixture - acceptance: `tools/drift_guard.py` records a census key counting how many REGISTRY-PUBLISHED buildings carry `mMaxPotential` versus how many do not, and a test asserts the absent-is-None branch against that census rather than against the synthetic corpus alone - tier: 2 - NOTE: this is the COMMON-MODE RISK named by the ADR 0006 adjudication on 2026-08-14. Both fences that ADR relies on read the SAME hand-authored corpus, so the registry-layer and solve-layer tests are one fixture read twice rather than two independent confirmations. That a registry-published `Building` can lack `mMaxPotential` AT ALL is asserted nowhere against the shipped data: the version pin records per-value counts (`"1.000000": 62`) but not WHICH entries carry the key, and ADR 0005 measured 62 entries carrying it while `clockspeed/data/registry.py:84-85` states 6 power-bearing entries carry no exponent - whether those sets overlap is unknown. It fails safe, because None cannot invent a number, so this is a premise risk rather than a correctness bug.

## Phase 3 - solver core follow-ups

CS-301 - Model the variable-power law once it is measured, and cover the two branches phase 3 could not exercise - acceptance: `clockspeed/solve/power.py` computes a draw for the three variable-power buildings and the one struct-range building instead of reporting them unmodeled, and tests cover a building whose un-sharded base is below the reference clock and a recipe naming two producing buildings - tier: 2 - NOTE: phase 3 deliberately refused to invent this. The semantics of `mVariablePowerConsumptionConstant` and `mVariablePowerConsumptionFactor` are unmeasured anywhere in this project - the registry only carries them - so `power.py` hands all four operands back verbatim and applies no law (non-negotiable 7). The two uncovered branches are stated honestly in that module rather than implied to be tested: no fixture building declares a base below the reference clock, and no fixture recipe names two producers.
CS-303 - Convert ADR 0006's name-fence on `Building.unsharded_clock_base` into a mechanical one - acceptance: an AST test forbids a direct `.unsharded_clock_base` read anywhere outside `clockspeed/solve/power.py`, with the test corpus exempted explicitly and by name rather than by a blanket path glob - tier: 2 - NOTE: raised by the ADR 0006 adjudication on 2026-08-14 as a roadmap candidate and explicitly NOT as a condition of that acceptance. Nothing mechanical currently stops a caller reading the field directly and clamping without going through `clamp_to_unsharded_base`; the ADR claims the name and the docstring as the fence and claims no more. Note that `tests/solve/test_synthetic.py::test_every_building_carries_the_unsharded_clock_base` reads the field directly by design and is one of the exemptions.
CS-302 - Measure `ratio.py`'s refusal path at real-registry scale - acceptance: the leave-one-out diagnosis that names the unproducible item is measured against a registry of the live size, and either shown acceptable or replaced - tier: 2 - NOTE: that diagnosis costs O(rows) extra exact solves and runs only on the refusal path. It was reasoned acceptable for optimizer-sized recipe sets and NOT measured at real scale, which is a stated limit rather than a claim.

## Phase 4 - save reader

CS-400 - Phase 4 gate: header, chunks, usmap, objects and world model, with unknown actor classes skipped and logged - acceptance: a real world parses, a corrupted save and a truncated save each produce a clean error rather than a crash, and a test proves the save directory is never opened for write - tier: 2
CS-401 - Assert world-token stability across a save and reload cycle, and tolerate an unseen token - acceptance: `WorldModel.token` is the header's saveIdentifier; two SYNTHETIC saves differing in name, play duration, chunk count and body content but sharing an identifier yield the same token, and a third with a different identifier yields a different one; a real-library test, skip-if-absent, asserts every save yields a 22-character base64url token, that the distinct-token count is strictly less than the file count, and that at least one token spans two different save versions - printing COUNTS ONLY and never a token value; and `load_world` on a token never seen before returns a normal `WorldModel` rather than raising - tier: 2 - NOTE: REWRITTEN 2026-08-14. The original acceptance ended "and the ledger treats an unknown token as a new world rather than failing", which is NOT SATISFIABLE IN PHASE 4: the ledger is `clockspeed/advisor/ledger.py`, which is phase 5 and does not exist. That clause moves to CS-500's acceptance, where the ledger exists. What remains here is the half phase 4 can actually prove, and it is the half that matters - the token is stable and the parser tolerates an unseen one.
CS-403 - Close the world-TOKEN half of CS-201 in the commit gate, now that a header parser exists - acceptance: with the package importable, an undeclared world token discovered from a real save header is blocked END TO END - stage a file carrying a SYNTHETIC token declared via an environment override, attempt a real `git commit`, observe exit 1 and HEAD unchanged; with `clockspeed` made UNIMPORTABLE, the gate still starts and prints today's honest skip; and with a deliberately corrupt save present, the gate still exits 0 on a clean file - tier: 1 - NEEDS ITS OWN FROZEN-FILE GRANT for `tools/precommit_gate.py`. NOTE: the seam question was settled by reading the line rather than by assuming. `docs/ARCHITECTURE.md:144` prohibits `clockspeed/` importing `tools/` and NOT the reverse, and `tools/drift_guard.py:194-217` already lazily imports `clockspeed.data.*` and states that direction is correct - so a gate importing a product module is NOT a seam violation. The real constraint is stated inside the frozen file itself at `tools/precommit_gate.py:643-649`: the gate must run in a checkout where nothing is installed and the package may be mid-edit and not importable at all, because a gate that cannot start does not block. So the design is a LAZY, function-local import that falls back to today's printed skip on ANY exception, bounded by a file cap and a timeout, with detection staying value-based per the CS-201 measurement. The CS-201 grant does NOT extend: adding an import of a product module into the gate's startup path introduces a new way for the gate to FAIL TO START, which is the one failure a gate must not have, and that is a larger risk class than CS-201's value matching or CS-202's message text.
CS-402 - Version-dispatch the save parser across the save versions present in the operator's own library - acceptance: ALL FOUR save versions parse through the same entry point and a test covers each, with header version handled independently of save version and every one of the three header versions covered - tier: 2 - NOTE: the acceptance originally said "both save versions" and that was STALE.
