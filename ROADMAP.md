# Roadmap - OPEN work only

One line per item. No narrative. Shape:

```
CS-nnn - <one line> - acceptance: <testable condition> - tier: <0|1|2>
```

Closed work lives in `docs/LEDGER.md`. Aspirational and conditional-trigger items live in
`BACKLOG.md`. Items blocked on something outside the repo live in `docs/GATED.md`. An item
is in exactly one of those four places.

**ID blocks.** IDs are permanent and never reused. `CS-0nn` is the phase 0 scaffold block
and is closed - those entries are in `docs/LEDGER.md`, not here. Open items are numbered
in the hundreds block matching their phase: `CS-1nn` phase 1, `CS-2nn` phase 2, and so on
through `CS-7nn`. Gaps are expected and are never backfilled.

**Not listed here:** phase 0, which is being completed now and closes into
`docs/LEDGER.md`. Spikes S4, S6 and S8 are also absent - they are being settled in this
session and their results land as ADRs in `docs/adr/` with the decisions recorded in
`docs/LEDGER.md`. If any of the three comes back unsettled, it is filed here as a new item
rather than left implicit.

**Do not advance past a phase whose acceptance criterion is unmet.**

CS-413 - Measure the object PAYLOAD grammar and make a real record's properties readable - acceptance: `ObjectRecord.body_offset` and `body_length` locate a real payload instead of reading 0 on every path, the object data section walks to its exact final byte on every real save of a measured pair, and `read_properties` returns at least one decoded property VALUE off a real building - each proven by a skip-if-absent real-library test reporting COUNTS ONLY - tier: 2 - **THIS IS THE PHASE-4 DEPTH GATE.** Filed 2026-08-15 by the operator ruling recorded in CS-400: CS-400's clause 1 closes when this closes, and phase 5 does not open before it. NOTE THE TWO LAYERS, because they are not the same problem and only the second is what most readers picture. **Layer 1 - the data section is not merely undecoded, it is UNLOCATED.** `clockspeed/save/objects.py:114-120` records that no fixture has ever built one and that `body_offset` and `body_length` "are 0 on every path today", so nothing in this project knows where any payload BEGINS. Layer 1 carries the only oracle a synthetic corpus cannot fake, and it is already computed: `ObjectTable.declared_body_length` minus `body_consumed` IS the data section, so a correct framing consumes that residual to its final byte - the same byte-exactness test that settled CS-407. **Layer 2 - the property grammar inside one payload**, then value decoding per type. Prior knowledge of how Unreal serializes properties is a HYPOTHESIS GENERATOR and never evidence here; the phase's stated common-mode risk is a corpus that only ever agrees with whoever wrote it, and for layer 1 the corpus can say nothing at all because no fixture builds a data section. Record the grammar as DATA, per CS-412 - a partial recorded as an adjective is not resumable.
